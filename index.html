Defcom

Use Pre-DHB to determine whether a defect can be safely fixed within the current release or should be taken to DHB. Use Post-DHB for Issue Impact × Change Risk disposition and controlled decision override.

Pre-DHB Decision Logic

The tool uses Fix Readiness × Release Fit. Safety or Regulatory/Compliance concerns override the matrix and require formal review.
Fix ReadinessHigh Release FitMedium Release FitLow Release Fit
HighFIX WITHIN RELEASEFIX WITHIN RELEASETAKE TO DHB
MediumFIX WITHIN RELEASETAKE TO DHBTAKE TO DHB
LowTAKE TO DHBTAKE TO DHBTAKE TO DHB
Fix Readiness considers root-cause understanding, fix identification, confidence, regression risk, and verification complexity. Release Fit considers effort, release timeline impact, and release phase.
Pre-DHB is a decision gate, not a prioritization score.

Issue Impact

How significantly does this defect affect customers, safety, compliance, or expected use?

Change Risk

How much risk or disruption would introducing the fix create for the release?
Scoring remains hidden until Evaluate.
